# Мутационное тестирование (Stryker.NET)

Покрытие строк врёт (код мог выполниться без проверок). Мутационный скор честен:
Stryker мутирует код пакета (инвертирует условия, выкидывает вызовы, меняет строки/константы)
и после каждой мутации гоняет тесты. Выживший мутант = тесты не ловят эту поломку.

## Запуск

Тул локальный, манифест `dotnet-tools.json` в git не лежит — при первом запуске поставить:

```bash
dotnet tool install --local dotnet-stryker
```

Прогон по одному пакету (~1 минута):

```bash
dotnet dotnet-stryker \
	--test-project tests/<Пакет>.Tests/<Пакет>.Tests.csproj \
	--project <Пакет>.csproj
```

Общие настройки (репортеры, пороги) — в корневом `stryker-config.json`.

## Разбор выживших

```bash
report=$(ls -td StrykerOutput/*/reports/mutation-report.json | head -1)
jq -r '.files | to_entries[] | .key as $f | .value.mutants[] | select(.status == "Survived") |
	"\($f):\(.location.start.line): \(.mutatorName) -> \(.replacement)"' "$report" \
	| sed 's|C:.devs.revealyan.rshared.src..*?\.||'
```

Каждого выжившего разложить на триаду:

1. **Реальная дыра** — изменение поведения, которое тест обязан ловить (логика, транзакции,
   маршрутизация, регистрации). Дописать тест, убивающий мутанта, и перезапустить Stryker.
2. **Низкая ценность** — тексты сообщений исключений, эквивалентные мутанты (рефактор-безопасные),
   только-производительность (например, пересборка кэша). Пометить в коде строкой выше:
   `// Stryker disable <mutator>: <причина по-русски>`.
3. **Непонятно** — показать пользователю и решить вместе. Молча глотать нельзя.

## Пороги

- < 60 % — чинить обязательно, PR не идти без разбора списка;
- 60–80 % — разобрать всех выживших (дynaмика важнее цифры);
- \> 80 % — норм, коротко отчитаться скором.

## Правила

- Отчёт пользователю всегда с числами: сколько мутантов, убито/выжило, скор.
- `StrykerOutput/` в git не попадает (в .gitignore).
- Гнаться за 100 % не нужно: disable с причиной — легитимный исход.
- Бланкетные `// Stryker disable all` запрещены.
